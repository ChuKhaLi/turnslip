What did Claude Code just change?

Last updated: 5 October 2026

At the end of a turn Claude Code tells you what it did. That reply is a summary, written by the model. The files on disk are the record, and the two do not always match: a file the reply never mentions, a key written into a config file, a deletion inside a shell command. Here are the ways to see what really changed.

Read the tool calls

Every edit Claude makes with its file tools shows in the conversation as an Update or Write line, and every shell command as a Bash line; expand them to see the details. This covers what Claude did through its tools. It does not tell you which files a command such as npm install or a build script changed, and in a long turn the lines scroll past.

Ask git

git status lists the changed and new files, and git diff shows the changes. It sees what Claude's tools and its shell commands did alike. Its limits: it compares with your last commit, so several turns and your own edits run together; it hides files your .gitignore excludes, such as a new key in .env; and it shows nothing in a folder that is not a git repository.

A slip after every turn

turnslip is a Claude Code plugin that snapshots the project when a turn starts and when it ends, and prints the difference as one line under Claude's reply, after Stop says::

turnslip · Added a login page · 2 files · 🔑 key added in config.js · /turnslip:undo
  • Per turn: only this turn's changes, shell commands included, so npm install shows up as packages changed.
  • What went unsaid: Claude ends its reply with a short receipt of the files it changed, which the screen hides unless Claude Code's verbose output is on. A file that changed but is missing from it shows as not mentioned: config.js; a file it lists that did not change shows as said but not changed: ….
  • Risky changes: 🔑 a key written to a file your .gitignore doesn't exclude, or a new .env, 🗑 deletions, 🗄 migrations, 📦 dependencies, 🚀 pushes and deploys, ⚠ writes outside the project.
  • Afterwards: /turnslip:undo takes the turn back. With Pro, /turnslip:history lists the recent turns of the project and /turnslip:report sums up the session.

Like git, turnslip never reads what your .gitignore excludes, and nothing it records leaves your machine.
